# Flow Matching Inversion Methodology (FMIM)

This repository provides the implementation of **Flow Matching Inversion Methodology (FMIM)** for observation-conditioned hydrogeological parameter inversion in subsurface multiphase-flow systems.

FMIM formulates inverse modeling as a conditional generative transport problem. Given transient dynamic observations, a modified U-Net predicts a conditional vector field, and posterior parameter-field realizations are generated by integrating an ordinary differential equation (ODE) from Gaussian initial states.

The repository is organized around four case studies:

1. **Case 1:** 2D heterogeneous multiphase displacement aquifer model
2. **Case 2:** 3D Brugge benchmark
3. **Case 3:** CO₂ sequestration model
4. **Case 4:** field-scale subsurface multiphase-flow case

```text

test_func.py     # posterior generation and diagnostic plotting
main.py          # case-level data loading, preprocessing, training, and inference entry point
utils.py         # utility functions
embedding.py     # conditional embedding module
```

`train_func.py` imports `Scheduler.GradualWarmupScheduler`. If the repository uses this scheduler, include the corresponding `Scheduler.py` file. Otherwise, replace it with a standard PyTorch learning-rate scheduler before release.

## Installation

Create a clean Python environment and install the dependencies:

```bash
conda create -n fmim python=3.10
conda activate fmim
pip install -r requirements.txt
```

Install the PyTorch build that matches your CUDA version. A CUDA-enabled GPU is recommended for training and posterior generation.

## Data organization

Each case expects paired datasets consisting of parameter realizations and corresponding transient dynamic responses. The exact file names and dimensions are defined in the case-specific `main.py` or preprocessing scripts.

Large data files are distributed through the GitHub Releases page rather than being tracked directly in the Git repository. Download the data package from the latest release:

```text
https://github.com/1422574239wj-tech/FMIM/releases/latest
```

For the current Case 1 implementation, download `2D.dataset.zip` from the release assets, extract it, and place the extracted files under the Case 1 data directory. The expected data layout is:

```text
datasets/Case1_2D_Aquifer/
├── grfv_perm1000.npz          # key: arr_0, prior permeability realizations
├── grfv_prior_data1000.npz    # key: arr_0, transient dynamic responses

```

The default Case 1 configuration is:

```python
image_size = (60, 60)
channels = 1
cond_dim = 900
ts_feature = [50, 18]
train_num = [0, 900]
test_num = [900, 1000]
```

Before running, update the data path in the case script. A portable option is to replace the hard-coded path with an environment variable:

```python
path = os.environ.get("FMIM_CASE1_DATA", "../datasets/Case1_2D_Aquifer")
```

Then set:

```bash
export FMIM_CASE1_DATA=/path/to/FMIM/datasets/Case1_2D_Aquifer
```

For other cases, arrange the required parameter ensembles, dynamic-response arrays, PCA objects, reference observations, and validation outputs according to the corresponding scripts.

## Training

For Case 1, set the run mode in `Case1_2D_Aquifer/main.py`:

```python
mode = 0
```

Then run:

```bash
cd Case1_2D_Aquifer
python main.py --epoch 500 --batchsize 16 --lr 2e-4 --num_steps 30
```

Typical outputs are:

```text
fmim_model.pth
ema_model.pth
data/train_loss.pkl
data/train_loss.png
```

Default training settings in the current Case 1 script are:

```text
training epochs: 500
learning rate: 2e-4
batch size: 16
U-Net base channel: 64
channel multipliers: [1, 2, 4]
optimizer: AdamW
EMA decay: 0.995
ODE sampling steps: 30
```

## Posterior generation

For Case 1, set:

```python
mode = 1
```

Make sure the trained weights are available in the case folder:

```text
fmim_model.pth
ema_model.pth
```

Then run:

```bash
cd Case1_2D_Aquifer
python main.py --num_steps 30
```

The script generates posterior parameter realizations conditioned on the reference observation vector and saves:

```text
post_data.h5
data/generated_images_test.png
data/generated_images_test_ori.png
```

The HDF5 output contains:

```text
/data
```

where each row is one generated posterior parameter realization flattened into vector form.

## Running the four cases

The four case folders follow the same general workflow:

1. Prepare prior parameter realizations and paired dynamic-response data.
2. Normalize the parameter fields and observation vectors.
3. Train the conditional vector-field predictor using the FMIM loss.
4. Generate posterior realizations from Gaussian initial states through ODE integration.
5. Reconstruct the physical parameter field if PCA is used.
6. Validate generated realizations through simulator-based forward evaluation when applicable.

High-dimensional cases may use PCA-based parameterization before network training. In that setting, FMIM is trained in the latent PCA space, and generated coefficients are mapped back to the original physical grid before validation.

---

## Notes on external simulators

This repository contains the neural-network implementation and case-level training/generation scripts. It does not provide a commercial multiphase-flow simulator. Forward numerical simulations, simulator input files, and post-generation physical validation should be handled separately according to the relevant simulator license and case setup.

---

## Reproducibility notes

- Use a fixed random seed when comparing posterior ensembles across methods.
- Keep the same train/validation/test split when reproducing manuscript results.
- Save normalization constants together with trained models.
- For PCA-based cases, save the PCA basis and mean vector used during training.
- Generated posterior fields should be evaluated by both parameter-space metrics and simulator-based data-space diagnostics.
